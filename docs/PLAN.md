## Decisions already made

- One monorepo. One Voyage source. One Tank source. The suite embeds them. Standalone Voyage Chief and Tank Chief stay available as optional builds of that same source.
- One install on the Proxmox server: all three apps and sync.
- Windows at 1366×768 and wider keeps today’s menu structure and order.
- Phones (smallest through current, portrait and landscape) and Android tablets get a touch-first menu with every Windows item still reachable.
- Phone home is four swipe panes: Voyage, Fuel, Tanks, Engine. Scroll-snap. Noon Report and Tank Soundings stay one tap away.
- Phone and tablet bottom bar: Home, Noon, Soundings, e-ORB, More. Same size, colour, and label; only the icon changes. e-ORB joins the bar from 360px wide; below that it lives in More.
- The phone-versus-desktop test uses a coarse pointer and a narrow viewport. Window height is not an input. `screen` size is not an input.
- Existing ship data keeps working: IndexedDB names, backup format strings, server JSON, and accounts.

## Proposed layout

Working tree once the sources have been promoted (milestone 2), still vanilla files, no bundler required to run:

```
apps/shell/            ChEng Suite shell (today apps/web)
apps/voyage/           the only Voyage Chief SPA + Python sync-server
apps/tanks/            the only Tank Chief SPA + Express API
packages/ui/           tokens, icons, day/night, textures (from the mockups)
packages/shared/       files that are already byte-identical across products
server/                Node gateway (today server/)
desktop/               Electron wrapper
android/               generated by Capacitor; not hand-edited history
deploy/                one LXC install and update script
docs/
```

A product flag (`suite`, `voyage`, `tank`) chooses which entry HTML, which menu, and which Capacitor/Electron ids are packaged. The flag does not fork the calculators.

Standalone builds:

- Voyage Chief omits Tank items (no Soundings on the bar, no tank groups). On Windows it keeps Voyage’s own four groups, not the suite sidebar.
- Tank Chief omits Noon, ROB, and e-ORB. On Windows it keeps Tank’s own five groups.
- Inside the suite, Vessel Setup remains the only editor of shared identity. Standalone builds keep their own vessel screens.

Until milestone 3, the imported Cheng-Pro paths (`apps/web`, `modules/voyage`, `modules/tanks`) can stay so the current test script still runs. The layout above is the target, not the shape of the history-import commit.

### Option A — git subtree (recommended if v1 can still receive fixes)

Subtree records each tip as a merge and keeps the original commit ids reachable. A later hotfix on Voyage Chief can be brought across with `git subtree pull` without rewriting this repository. Blame and `git log` work for the prefixed paths.

Cost: the three full histories land under prefixes, so Voyage and Tank exist twice until the dedup milestone (once inside the Cheng-Pro import, once as the standalone import). Cheng-Pro is about 105 MB, Voyage about 12 MB, Tank about 14 MB, plus pack overhead. Tank’s two `.xlsm` workbooks (about 7 MB) and Cheng-Pro’s `world_port_index.zip` come along.

Example, on a `cheng-suite` clone, after approval:

```
git subtree add --prefix=history/cheng-pro \
  https://github.com/tsogs66/Cheng-Pro.git \
  2f0b79bbd932e41dd224d07ac45864843e0bfe67

git subtree add --prefix=history/voyage-manager \
  https://github.com/tsogs66/voyage-manager.git \
  5ff73749b1386d05e69b7290aae525a7f4d75cb5

git subtree add --prefix=history/tank-management \
  https://github.com/tsogs66/tank-management.git \
  71c011b28679ecd7355e144b3b9bf149c0d46946
```

Later hotfix, same prefix:

```
git subtree pull --prefix=history/voyage-manager \
  https://github.com/tsogs66/voyage-manager.git main
```

The pull still has to be replayed onto `apps/voyage/` by hand or by a reviewed patch. Subtree does not update the deduplicated tree by itself.

### Option B — git filter-repo, then merge

Clone each repository, rewrite paths with `git filter-repo --to-subdirectory-filter`, drop blobs that v2 will not ship, then `git merge --allow-unrelated-histories` into `cheng-suite`.

This produces a cleaner first tree and a smaller pack if the workbooks and the port zip are stripped. The commit ids no longer match GitHub, so a later v1 fix cannot be merged by SHA. The rewrite is repeated, with the same path map, for every hotfix. `filter-repo` is run only on those clones. The original GitHub repositories are not rewritten and are not pushed to.

Choose B if v1 is frozen at the pins above and a smaller repository matters more than `subtree pull`.

### Option C — snapshot copy

Copy the trees without history. This is how AIO’s `modules/` arrived. It is the smallest repository and the weakest blame. With about three thousand commits of noon-report and sounding fixes behind these files, a snapshot throws away the reason a formula looks the way it does. Use C only as a fallback if A and B are rejected.

### Not used

Git submodules would leave Voyage and Tank edited in the old repositories. That fights the single-source decision.

### Recommendation

Use option A. Put the three tips under `history/` and leave them there as the archive. Milestone 2 copies the Cheng-Pro tip into the working paths (so `npm test` has a known-good tree). Milestone 3 replaces `modules/voyage` and `modules/tanks` with one tree each, using the standalone histories for blame when a line is older than the AIO divergence. Record the chosen option in this file before anyone runs it.

Large blobs to decide before the import (open question 6): Tank’s `TANK MANAGEMENT *.xlsm` workbooks, Cheng-Pro `world_port_index.zip`, `edit-map.png`, and the empty file `1` at the Voyage root.

## Dedup of the embedded copies

Do not delete a copy because the other file “looks like the source.” On these pins the programs have already forked.

Voyage Chief versus `Cheng-Pro/modules/voyage/www`:

- Different: `voyage_manager.html` (standalone 1,961,347 bytes, `e4a0e192`; AIO 2,000,085 bytes, `315afa45`). AIO’s `index.html` is a byte-for-byte second name for that AIO HTML. CI fails if those two names drift.
- Different: `save-file.js`, `sw.js`.
- Present only on the AIO copy: `count-up.js`, `hud-effects.css`, `num-align.js`, and a `tests/` directory.
- Same blob today, among others: `eorb.js`, `clock-picker.js`, `consumption-plan.js`, `theme.js`, `ui-zoom.js`, `file-viewer.js`, `license.js`, `ship_time.js`.

Tank Chief `public/js` versus `Cheng-Pro/modules/tanks/public/js`:

- Different: `api.js`, `app.js`, `bunkering-core.js`, `bunkering-report.js`, `fuel-report.js`, `license-config.js`, `node-shim.js`, `save-file.js`, `store-core.js`, `tank-sounding-card.js`.
- Present only on the AIO copy: `cheng-bridge.js`, `count-up.js`, `num-align.js`, `tank-card-capture.js`.
- Same blob today: the rest of that directory, including `db.js`, `calc.js`, `theme.js`, `ui-zoom.js`, `clock-picker.js`.

`store-core.js` is the sensitive one. The AIO copy adds license-email scopes and the shared vessel fields. The standalone copy does not. Taking the standalone file would drop suite behaviour. Taking the AIO file without a diff would drop any standalone-only fix from the 2.2.83 release.

Same-day releases: Cheng-Pro `2f0b79bb`, Voyage `5ff73749`, and Tank `71c011b2` all merged within a few minutes on 2026-11-27. “AIO is newer” is not a safe rule. The first dedup commit is a written diff (file, which side, why), reviewed before any file is deleted.

Rules for the single source:

1. Suite behaviour comes from the AIO copy where the files differ, after the diff is accepted line by line.
2. A line that exists only on the standalone tip is ported or explicitly dropped in that diff.
3. Files with the same blob on all tips move to `packages/shared/` only after a CI check hashes them. Candidates already identical: `theme.js`, `ui-zoom.js`, `clock-picker.js`, `file-viewer.js`, `signed-numeric-input.js`, `consumption-plan.js`, `note-reminders.js`, `loading-splash.js`, `stem-advice.js`, `tank-fuel-register.js`.
4. `voyage_manager.html` stays one file. The gateway may keep serving it under both `index.html` and `voyage_manager.html` until a later milestone. The CI `cmp` stays until that second name is gone.
5. `copy-embedded.js` stays until the on-device route copy is generated in CI from the one Tank server tree, or checked the same way it is today.
6. Standalone entry points are build flags and menus, not directories of forked JavaScript.

## Risks

| Risk | What keeps it small |
| --- | --- |
| Diverged copies | Milestone 3 is a reviewed diff. Same-day tips are both inputs. |
| IndexedDB looks empty after an upgrade | Keep database names, app ids, the Electron user-data directory, and the loopback origin. Backup files remain the escape hatch. |
| Renaming the product moves Electron’s profile | Freeze the user-data path. A display-name change must not change that path. |
| Voyage’s Windows install is a PowerShell loopback server under `%LOCALAPPDATA%\NoonReport`, not Electron | Do not point the suite EXE at that folder. A standalone upgrade keeps that launcher until a reviewed migration copies `noon-report-db-v1`. |
| Height or `screen` size brings the phone bar back | One shared predicate. The inline boot script is the same function. A test locks it. |
| Two-megabyte Voyage HTML | Do not split or retheme it in the same review as the import or the nav predicate. |
| Service worker serves a stale shell | Keep `Cache-Control: no-store` on HTML, JS, and CSS, as the gateway does now. |
| License secrets regenerated on install | The update script creates `/root/cheng-pro.env` only when it is missing. v2 must copy the file. A new token invalidates seats and the admin password. |
| `git clean` or a redeploy deletes vessel JSON | Data lives outside the git checkout (`/var/lib/cheng-suite`). The update never seeds over an existing data directory. |
| Capacitor 7 (Voyage) versus Capacitor 6 (AIO and Tank) | Leave the Android projects alone until milestone 11. Unify majors only with an in-place APK upgrade test. |
| Mockups still in draft | Tokens land behind a flag. Nav parity can proceed from the README tables. Pixel work waits if the mockup PR changes. |
| History import is large | `history/` is the archive. Reviewers look at the milestone 3 diff, not at three thousand imported commits. |
| Open voyage leg dropped on sync | Already a suite rule. Milestone 8 re-checks it. |
